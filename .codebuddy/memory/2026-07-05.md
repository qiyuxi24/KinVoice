## P0 #1: 统一 family_id 类型 (Integer → String)

- `backend/app/services/family_service.py` — get_user_family_id 注释更新，明确 user_id="1" 为兼容路径

- 保留 user_id="1" → family_id="1" 的兼容路径，等 P0#2-#4 完成后移除

- 解耦设计：models/schemas/api 三层各自独立修改，无交叉依赖


## P0 #2: 统一 user_id 传递方式 (Header Depends)

### 核心原则
- 后端全部通过 `X-User-Id` Header + `Depends(get_user_id)` 获取 user_id
- 前端 `ajax.js` 自动注入 `X-User-Id` Header（从 `userIdentity.getUserId()`），各 API 模块无需手动传
- 废弃 body/query 参数中手动传 `user_id` 的方式

### 后端改动
| 文件 | 改动 |
|------|------|
| `schemas/chatroom.py` | SendMessageRequest 移除 `user_id` 字段 |
| `schemas/profile_ai.py` | ProfileUpdateRequest 移除 `user_id` 字段（改为空模型） |
| `api/chatroom.py` | send_message/get_messages/list_conversations: 全部改用 `Depends(get_user_id)` |
| `api/family.py` | 移除 4 个内联的含 user_id 请求模型，改用 schemas/family.py 的纯业务模型 + `Depends(get_user_id)` |
| `api/profile_ai.py` | update_dynamic/update_stable/read_profile: 全部改用 `Depends(get_user_id)` |

### 前端改动
| 文件 | 改动 |
|------|------|
| `ajax.js` | 新增 import userIdentity，fetchPromise 中自动注入 X-User-Id Header |
| `chatroom.js` | 移除 uid() 辅助函数 + 3 处手动 user_id 传参 |
| `family.js` | 移除 uid() + 5 处手动 user_id 传参 |
| `profile_ai.js` | 移除 3 处手动 user_id 传参，3 个方法全部改为无参 |
| `Companion/index.ux` | updateDynamic('default') → updateDynamic() |
| `Profile/index.ux` | updateStable('default') → updateStable() |

### 验证
- 所有后端 API 零 lint 错误
- 重建数据库成功
- get_user_id 中间件兼容模式保留（无 Header 时默认 "1"）


## 新增：用户登录系统（账号密码）

### 设计
- **账号体系**：用户名 + 密码（替代设备 UUID），密码用 PBKDF2-SHA256 加盐哈希
- **注册/登录 API**：`POST /auth/register`（username + password + nickname）→ 返回 user_id；`POST /auth/login`（username + password）→ 返回 user_id + nickname
- **Profile 页面**：未登录时显示"点击登录"，点击头像展开登录/注册面板；已登录时显示"你好，{昵称}" + 家庭组信息 + 退出按钮
- **后端 user_id**：服务端生成 UUID（`uuid.uuid4()`），不再依赖前端 device UUID

### 新增/修改文件
| 文件 | 改动 |
|------|------|
| `backend/app/models/family.py` | User 新增 `username`(unique)、`password_hash` 字段 |
| `backend/app/utils/password.py` | 新建：PBKDF2-SHA256 密码哈希/验证工具 |
| `backend/app/schemas/auth.py` | 新建：RegisterRequest、LoginRequest、AuthResponse |
| `backend/app/api/auth.py` | 新建：POST /auth/register、POST /auth/login |
| `backend/app/main.py` | 注册 auth_router |
| `src/helper/apis/auth.js` | 新建：login()、register() |
| `src/helper/userIdentity.js` | 重写：登录态管理（init/login/register/logout/isLoggedIn），本地存储 user_id + nickname |
| `src/pages/Profile/index.ux` | 重写：登录态检测、登录/注册面板 UI、退出登录 |

### 用法
- cd backend && del data\kinvoice.db && python init_db.py（重建库）
- Profile 页面 → 点击头像 → 输入用户名密码登录
- 登录后 user_id 存入 localStorage，后续所有 API 请求自动携带


## 记忆传承卡片简化：去掉 NVC 模型，对齐前后端 API

### 核心变更
- **去掉 NVC 四要素**（observation/feeling/need/request），卡片简化为：type, category(即前端 tag), title, content, author, emotion
- **Card 模型新增 `author` 列**（String(100)），不再用 `request` 字段存 "来自xxx"
- **默认 type 从 "nvc" 改为 "simple"**

### 后端改动
| 文件 | 改动 |
|------|------|
| `models/card.py` | 新增 author 列，to_dict() 增加 author |
| `schemas/memory.py` | CardCreate 主字段改为 type/category/title/content/emotion/author，NVC 字段仍保留 Optional 兼容；CardOut 新增 author |
| `api/memory.py` | create_card 默认 type="simple"；sync 端点的 LocalCard 简化为 6 字段（id/tag/title/content/author/emotion/date），映射直接对齐不再扭曲 |

### 前端改动
| 文件 | 改动 |
|------|------|
| `pages/Memory/index.ux` | 删除 9 条 mock 假数据；onInit 改为后端优先加载（GET /cards → cardFromBackend 转换），失败回退本地缓存；localToPayload 简化为直传 type/category/title/content/author/emotion；新增加载状态 + 空状态 UI |
| `apis/cards.js` | 新增 favorite() 方法；list 增加 type 参数；limit 默认改为 50 |

### 数据流
- **加载**：GET /cards（后端优先） → 后端为空时读 localStorage → 有本地数据则 sync 到后端
- **创建**：POST /cards {type:"simple", category, title, content, author, emotion}
- **更新**：PUT /cards/{id} 同结构
- **同步**：POST /cards/sync {cards: [{id, tag, title, content, author, emotion, date}]}

### 保留兼容
- Card 模型 NVC 列仍然存在（nullable），旧数据不受影响
- summarize 服务继续用 NVC 术语做 LLM 提取，后续可独立优化


## 传承页改造：硬分类 → 用户自定义文件夹

### 改动动机
- 原来 4 个固定分类（人生阅历/家庭菜谱/成长故事/相处感悟）太僵化，用户无法按自己的方式组织笔记
- 改为"文件夹+笔记"模式，类似 Notion/Apple Notes 的组织方式

### 后端新增/改动
| 文件 | 改动 |
|------|------|
| `models/folder.py` | 新建：Folder 表（id, name, family_id, created_at） |
| `models/card.py` | Card 新增 `folder_id` FK → Folder.id + folder relationship |
| `schemas/memory.py` | 新增 FolderCreate/Update/Out/ListOut/DeleteResponse；CardCreate/Out 新增 folder_id |
| `api/memory.py` | **新增文件夹 CRUD**：GET /folders（含 note_count）、POST /folders、PUT /folders/{id}、DELETE /folders/{id}（笔记自动归入未分类）；卡片查询支持 `?folder_id=` 参数，folder_id=0 查未分类 |
| `init_db.py` | 新增 migrate_category_to_folder()：旧 category → 同名文件夹 + 设置 folder_id |
| `main.py` | import app.models.folder 确保建表 |

### 前端改动
| 文件 | 改动 |
|------|------|
| `pages/Memory/index.ux` | **完全重写**：顶部横滚文件夹药丸列表（全部/各文件夹/+新建）、选中文件夹显示笔记、"全部"视图下显示 folderName、浮动 FAB 新建按钮、笔记弹窗内含文件夹选择器、文件夹弹窗支持新建/重命名/删除 |
| `apis/cards.js` | 新增 listFolders/createFolder/renameFolder/deleteFolder；list 支持 folder_id 参数 |

### 数据模型
```
前端 note = { id, folder_id, folderName, title, content, author, emotion, date }
后端 Card = { id, type:"simple", folder_id, title, content, author, family_id, ... }
后端 Folder = { id, name, family_id, note_count }
```

### UI 交互
- 文件夹横滚条：选中高亮（蓝色），显示笔记计数
- 全部视图：显示所有笔记，每张卡片带 📁文件夹名
- 创建笔记：弹出面板内可横向滚动选择目标文件夹
- 文件夹设置（⋮）：重命名 / 删除（笔记保留，移入未分类）
- 空文件夹删除后，笔记归入 folder_id=NULL，前端在全部视图中仍可见


## 传承页二次精简：只保留两个入口

### 改动原因
- 用户反馈页面元素过多（标题、文件夹条、section 标题、新笔记按钮、FAB、文件夹设置等），要求只保留「新建文件夹」和「新建卡片」两个主要操作。

### 后端改动
| 文件 | 改动 |
|------|------|
| `api/memory.py` | 文件夹接口从 CRUD 精简为只保留 `GET /folders`、`POST /folders`；删除 `PUT /folders/{id}`、`DELETE /folders/{id}`；列表不再插入 id=0 的"未分类"虚拟文件夹 |
| `schemas/memory.py` | 删除 `FolderUpdate`、`FolderDeleteResponse` |

### 前端改动
| 文件 | 改动 |
|------|------|
| `pages/Memory/index.ux` | **重写**：删除 section header、FAB、文件夹设置弹窗；底部固定操作栏只有两个按钮「新建文件夹」「新建卡片」；文件夹条仅用于筛选；卡片弹窗保留文件夹选择器 |
| `apis/cards.js` | 删除 `renameFolder`、`deleteFolder` |

### 说明
- 数据库表结构未变（仍保留 `folders` + `cards.folder_id`），因为两个入口正好对应这两张表。
- 未分类卡片（folder_id=NULL）不再显示单独筛选，仅在「全部」中可见。
