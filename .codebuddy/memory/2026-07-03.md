## 前后端通讯检查与修复

### 发现并修复 1 个关键 Bug

**问题**: BreakIce 页面 `POST /convert` 字段名不匹配
- 前端发送 `{ raw_text: "..." }` 但后端 schema 要求 `text` 为必填字段
- 导致 Pydantic 422 校验失败，转换功能不可用

**修复**:
1. `backend/app/schemas/convert.py`: `text` 从 `Field(...)` 改为 `Field(None)`（可选）
2. `backend/app/api/convert.py`: 增加空值校验 `raise HTTPException(400)`，顶部补充 `HTTPException` import

### 接口测试结果（8/9 通过）

- ✅ GET /ping、POST /cards(id=1)、PUT /cards/1、GET /cards(total=1)、POST /cards/sync(total=2,+1)、DELETE /cards/1、GET /profiles(total=0)、POST /convert(raw_text accepted)
- ❌ POST /chat → 500（LLM_API_BASE 未配置，非代码问题）

### 修复数据库 schema 不一致

删除旧 `kinvoice.db`（缺少 type 列），用 `init_db.py` 重建 → 所有 CRUD 正常。

### 错误码分段

| 段 | 范围 | 说明 |
|---|---|---|
| 1xxx | 网络层 | fetch timeout/DNS/SSL/连接拒绝 |
| 2xxx | HTTP 状态码 | 400~504 全部映射 |
| 3xxx | 业务层 | convert/chat/cards/profiles 具体场景 |
| 4xxx | 存储层 | storage 读/写/满 |
| 5xxx | 校验层 | 前端参数校验 |

### 后端 detail → 业务码映射

`DETAIL_TO_CODE` 数组支持精确/包含匹配，将后端 `detail` 字段自动映射到业务错误码。
