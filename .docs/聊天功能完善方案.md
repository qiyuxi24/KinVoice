## 一、待完成功能清单

### 1. 聊天列表页（ConversationList）

**现状**：聊天列表通过 `GET /chatroom/conversations` 已有后端支持，但前端没有对应页面。

**需求**：
- 新建 `pages/ConversationList/index.ux`
- 展示私聊列表（显示对方昵称 + 最后消息 + 时间）
- 展示群聊入口（显示"家庭群聊" + 成员数 + 最后消息 + 时间）
- 空状态：提示"暂无聊天，去家庭组添加成员吧"
- 点击进入对应 ChatRoom（带上 chatType、peerId、peerName 参数）

**路由参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `conversation_id` | number | 已有会话 ID |
| `type` | string | `"private"` / `"group"` |
| `peer_id` | string | 私聊对方 user_id |
| `peer_name` | string | 私聊对方昵称（URI 编码） |

### 2. 家庭组成员 → 发起私聊

**现状**：`Family` 页面展示成员列表，但成员不可点击。

**需求**：
- 每个成员项添加 `onclick` 事件
- 点击非自己成员 → 跳转 `ChatRoom`，传 `type=private&peer_id=xxx&peer_name=xxx`
- 自己不能和自己私聊（标记"(我)"的不可点击）

**修改文件**：`src/pages/Family/index.ux`

### 3. 家庭组群聊入口

**现状**：`Family` 页面没有群聊入口。

**需求**：
- 在成员列表上方/下方添加"进入群聊"按钮
- 点击 → 跳转 `ChatRoom`，传 `type=group`
- 仅在已加入家庭组时显示

### 4. ChatRoom 页面完善

**4.1 未加入家庭组时的群聊处理**

当前 ChatRoom 在群聊模式下调用 `chatroomAPI.getConversations()` 查找已有群聊。如果用户未加入家庭组，后端 `/chatroom/conversations` 不会返回群聊，`conversationId` 保持 null，发送消息时后端返回 `400 "你还没有加入家庭组"`。

需改善：
- `onInit` 时检测家庭组状态
- 未加入家庭组 → 显示空状态 + "先去加入家庭组"引导按钮

**4.2 首次进入私聊的无缝体验**

当前 `ChatRoom` 在私聊模式下：
- 先调 `getConversations()` 查找已有私聊 → 找到则用已有 conversationId
- 找不到 → conversationId 为 null
- 发送第一条消息时 → `sendMessage()` 不传 `conversation_id` → 后端自动创建

这个流程本身是正确的。但需处理 `loadMessages()` 在 `conversationId` 为 null 时直接返回空列表，页面上显示"暂无消息，开始聊天吧"。

**4.3 轮询优化**

当前：固定 2 秒间隔轮询。需改进：
- 页面可见时轮询，隐藏时停止（已实现 ✅）
- 发送消息后立即拉取一次（减少延迟）
- 网络错误时指数退避（2s → 4s → 8s → 最多 30s）

**4.4 消息时间显示**

当前：消息无时间戳。需添加：
- 每条消息显示 `created_at`（格式：`HH:mm`，跨天显示 `MM-DD HH:mm`）
- 两条消息间隔 > 5 分钟时显示时间分隔线

**4.5 发送失败重试**

当前：发送失败时消息标记为"(发送失败)"，无法重试。需添加：
- 失败消息右侧显示红色重试图标
- 点击重试图标 → 重新发送该消息
- 重新发送成功后替换消息

**4.6 滚动优化**

当前：`scrollToBottom` 使用 100ms 延迟，可能不准确。需改进：
- 新消息到达时，如果用户已在底部 → 自动滚到底部
- 如果用户正在查看历史消息 → 不自动滚动，显示"新消息"提示条

### 5. AI 对话历史

**现状**：`Companion` 页面的 AI 对话历史保存在 `conversations` 表中（type="ai"），但聊天室 API 刻意过滤了 `type=ai`。

**需求**：AI 对话作为一个特殊"聊天"展示在聊天列表或陪伴页中。

**方案**：
- `GET /chatroom/conversations` 增加 `include_ai` 参数
- 或在 Companion 页面内置对话历史列表
- 或新增独立的 AI 对话历史页面


## 三、路由参数规范

从其他页面跳转到 ChatRoom 时传递的参数：

```js
// 私聊（从成员列表发起）
router.push({
  uri: '/pages/ChatRoom',
  query: {
    type: 'private',
    peer_id: member.user_id,
    peer_name: encodeURIComponent(member.nickname),
  }
})

// 群聊（从家庭组发起）
router.push({
  uri: '/pages/ChatRoom',
  query: {
    type: 'group',
  }
})

// 从聊天列表进入已有会话
router.push({
  uri: '/pages/ChatRoom',
  query: {
    type: conv.type,
    conversation_id: conv.id,
    // 私聊额外参数
    peer_id: conv.peer_user_id,
    peer_name: encodeURIComponent(conv.peer_nickname),
  }
})
```

## 四、异常场景处理

| 场景 | 处理方式 |
|------|----------|
| 未加入家庭组 → 点群聊 | ChatRoom 显示空状态："你还没有加入家庭组" + 按钮"去加入" |
| 私聊对方已退出家庭组 | 消息发送失败，后端返回 400，前端提示"对方已不在家庭组中" |
| 网络断开 → 轮询失败 | 静默处理，不弹 toast；网络恢复后自动恢复轮询 |
| 发送超时 | 消息标记"发送失败"，显示重试按钮 |
| 首次加载消息失败 | 显示"加载失败，点击重试" |
| 轮询返回 403 | 用户被移出家庭组，显示"你已不在该家庭组中"，停止轮询 |
